sql инъекция
сайт делает запрос к базе данных
SELECT * FROM users WHERE name = 'sigma'

если ввод не фильтруется можно ввести ' OR '1' = '1
запрос становиться SELECT * FROM users WHERE name = '' OR OR '1' = '1'
OR '1' = '1' всегда true - получаешь всех пользователей. вот и уязвимость

xss cross-site scripting - внедрение в javascipt страницу
<script>alert('взломано')</script>
<script>document.body.innerHTML='<h1>cracked!</h1>';</script>

если сайт не фильтрует ввод и отображает его - скрипт выполниться у всех кто откроет страницу. можно украсть куки, перенаправить на фишинг

lfi(local file inclusion) - чтение файлов сервера
example.com/page?file=../../../etc/passwd

rce(remote code execution)
выполнение своего кода на сервере
уязвимость срабатывает если ты к примеру вместо картинки закинешь php файл. работает в том случае если загрузчик уязвим и не фильтрует поступившие файлы

csrf(cross site request forgery)
заставит браузер жертвы сделать запрос от его имени
например жертва заходит на твой сайт а там скрытая форма которая переводит деньги с её счёта

idor(insecure direct object reference)
доступ к чужим данным через изменение id
site.com/profile?id=123 <- твой профиль
site.com/profile?id=124 <- чужой профиль
если сервер не проверяет права - видишь чужие данные
